# Portals Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Super admin console, passenger accounts with a statement, and top-up requests the admin fulfils.

**Architecture:** Money rules and authority live in Postgres security-definer functions (migration 0022). The only signature check — the phone proving it holds the wallet it links — lives in `settleBatch()` like every other one. Three lazy-loaded portals share one shell and stylesheet.

**Tech Stack:** React 19 + Vite PWA, Supabase Postgres + Auth + one Edge Function, tweetnacl, PGlite for proofs, WebAuthn.

**Spec:** `docs/superpowers/specs/2026-09-17-portals-design.md`

## Global Constraints

- `protocol/` stays platform-free; run `npm run sync:protocol` after touching it.
- All four proofs (`npm run proof:all`) pass before every commit.
- A sync batch is verified only in `settleBatch()`; adapters supply ledger methods only.
- No admin power in the browser: every admin action is a SQL function that checks `is_platform_admin()`.
- Top-up amount 10–10000 NPR; methods `esewa`, `khalti`, `fonepay`, `imepay`; unique `(method, reference)`.
- Link freshness 300 s, same as `TAP_MAX_AGE_S`.
- Portal classes use the `op-` prefix; never reuse `.panel`, `.card`, `.chip`.
- Release order: `supabase db push` → sync:protocol + function deploy → `vercel deploy --prod`.

### Task 2: Money for accounts — statement, top-up requests, corrections, suspension, admin authority

**Files:**
- Modify: `supabase/migrations/0022_portals.sql` (append)
- Test: `scripts/legs-proof.mjs` sections 16–19

**Interfaces (SQL, all security definer, `search_path = public`):**
- `my_account() -> jsonb` `{ linked, wallet, balance, overdraft, suspended, email }`
- `my_statement(p_limit int default 200) -> jsonb` `{ balance, entries: [{ at, kind, title, detail, amount, balance_after }] }`; kinds `topup`, `refund`, `adjustment`, `ride`, `stage_fare`.

- `admin_overview() -> jsonb`, `admin_passengers(p_query text) -> jsonb`, `admin_statement(p_wallet text) -> jsonb`, `admin_operators(p_query text) -> jsonb`, `admin_topup_requests(p_status text) -> jsonb`.
- `admin_load_topup(p_id bigint) -> jsonb` (reasons `not_admin`, `not_found`, `already_decided`), `admin_reject_topup(p_id bigint, p_reason text)`, `admin_load_cash(p_wallet text, p_amount int, p_note text)`, `admin_adjust_wallet(p_wallet text, p_amount int, p_reason text)` (reasons `reason_required`, `below_floor`), `admin_set_suspended(p_kind text, p_id text, p_suspended bool)`, `admin_set_setting(p_key text, p_value text)`.

- `current_operator_id()` returns null for a suspended operator; `my_operator()` adds `suspended`.
