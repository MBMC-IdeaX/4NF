### Crew economics

The roadmap item this session started on. A conductor signs on at `/crew` with a
**CR1** token their own phone signs — their key, the bus, the minute — and a
clean trip pays them Rs 50. A trip is clean when it carried at least 5 rides,
never lost its power, never overrode the capacity interlock, and metered nothing
the plausibility score calls `high`.

The rule lives in exactly one place: SQL counts the evidence (`trip_evidence()`),
`cleanTripVerdict()` in `protocol/crew.mjs` rules on it, and `award_clean_trip()`
owns the money and the once-only rule. Do not re-implement the clean rule in SQL
— the `TAP_MAX_AGE_S` duplication is the standing warning about what that costs.

The money is not minted. Bhada owes the operator the fares their vehicles
collected; the bonus is Rs 50 moved out of that payable into the crew member's
wallet, both sides in one `crew_bonuses` row, on `wallet_for(crewKey)`.

`assessPower()` decides when a charger going away is a pulled 12 V feed: gone for
120 s on a bus whose odometer moved inside the last 600 s. A parked bus loses the
same socket and raises nothing. It lands in `meter_events`, deliberately not in
`door_events` — the door tape is the interlock record a regulator reads.

### The interface

Bhada now runs **two visual registers on purpose**, and this is the thing most
likely to be undone by accident:

- **Printed matter — the bus.** Meter console, door terminals, passenger ride
  card. Ticket stock, hard rules, no shadows, big figures. Read at arm's length
  in daylight by someone holding a rail. **Do not modernise these.**
- **App — the portals and the public site.** White surfaces on a cool ground,
  soft radii, one shadow ramp, 48px minimum tap targets, 16px inputs (anything
  smaller makes iOS zoom on focus). The comparison in a user's head is eSewa,
  Khalti or their bank, so the job is familiarity rather than novelty.

New files: `src/portals/shared/portal-app.css` (loaded after `portal.css` and
`portal-v2.css`, which it overrides), `src/styles/site-app.css` (after
`surfaces.css`), and `src/portals/shared/Icon.jsx` — a hand-drawn stroke icon set
rather than a library, because the app is precached onto phones over 2G.

Rules the app register keeps: one accent, and it marks the primary action only;
money in is green and money out is ink, with the sign always written; a surface
gets a hairline **or** a shadow, never both; every list has a loaded, loading,
empty and error state.

## How to run it

```bash
npm run proof:all      # all four proofs — required green before any commit
npm run build
npm run sync:protocol  # after ANY edit under protocol/
```

Release order is **database → function → site**, because the client uploads legs
in a shape only the new function understands:

```bash
supabase db push
npm run sync:protocol && supabase functions deploy sync --no-verify-jwt
git push origin master          # Vercel builds from the push now
```

### Looking at the portals without a login

```bash
BHADA_FIXTURES=1 npm run build   # or npm run dev
```

Swaps the Supabase client for `src/lib/supabase-fixtures.js` through a resolver
plugin in `vite.config.js`. A normal build cannot reach it. Use it for any work
on how the office screens look; it is how the truncated-money bug was found.

It renders screens. It says nothing about row-level security or the SQL behind
the views — that is what `npm run proof:legs` is for.

  that changes.
- **The account portal's linked-wallet state.** It needs device keys the

- **Row-level security on the new views** beyond what `proof:legs` section 18
  covers for `admin_*` functions.
- Nothing has been tested by a real conductor or a real passenger.

## Traps

- A service worker will serve the **old** `index.html` after a deploy. Unregister
  it and clear caches before judging what is live, or you will review the
  previous build and think nothing shipped.
- `data__body` on the landing page is a **paragraph**, not the stat grid. The
  four proof figures are `.strip`.
- Several landing sections were authored for a dark ground and drop to about
  2:1 contrast if the ground flips without them being turned over explicitly —
  `.trust__list` and `.strip` especially.
- `register_meter()` freezes the first key it sees for a plate. Never let a test
  device key bind to a real plate; the live plates `BA2KHA4412` and
  `BA5KHA2087` are still unkeyed and must stay that way until a real box
  registers.
- `SIGNUP_CREDIT_NPR` is set on the live function, so every new wallet starts
  with Rs 2000. Unset it before real money.
- A conductor with no Bhada wallet gets a `no_wallet` row rather than a payment.
  That is deliberate; they sign up and the next trip pays.
